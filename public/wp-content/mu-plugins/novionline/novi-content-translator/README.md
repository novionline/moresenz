## Novi Content Translator

Translate WordPress/Gutenberg `post_content` (block markup) for NoviOnline, with special handling for NectarBlocks so translated content stays **block-valid** in the editor.

This plugin is used by our duplication/translation flows to create a translated version of a post while preserving Gutenberg block structure.

## Requirements

- PHP 8.1+ (matches project runtime)
- [Composer](https://getcomposer.org/) (for test dependencies)

## What it does

- **Block-aware translation**: parses blocks, translates configured fields, and serializes back to valid Gutenberg markup.
- **NectarBlocks compatibility**: uses an **attrs-first** strategy for certain NectarBlocks where Gutenberg validation depends on `save()` output matching attributes.
- **Reusable blocks** (`core/block`): if a referenced reusable block has a Polylang translation for the target language, the `ref` ID is swapped; otherwise it stays as-is.

## How it works (high level)

- Parse `post_content` into blocks (`parse_blocks`)
- Pre-transform blocks for target language (e.g. reusable block `ref` swapping)
- Translate supported fields per block type (e.g. `attrs.content`, `attrs.text`, `attrs.title`)
- Sync attributes ↔ markup when required (NectarBlocks “attrs-first” rules)
- Serialize blocks back to `post_content` (`serialize_blocks`)

## Notes for NectarBlocks

- **Do not edit `dist/` files** in NectarBlocks theme/plugin. They are generated via webpack.
- Some blocks (text/button/icon-list-item/accordion-section) are handled via **attrs-first** rules to avoid “Block validation failed” errors.
- Accordion sections are strict about wrapper/placeholder alignment; translation must not move inner blocks outside the `__content` wrapper.

## Setup (for tests)

Install Composer dependencies:

```bash
cd "public/wp-content/mu-plugins/novionline/novi-content-translator"
composer install
```

## Node / Webpack (admin/editor assets)

This plugin bundles its admin/editor assets from `assets/js/` and `assets/scss/` into `dist/` using webpack, and writes a hashed `manifest.json` for PHP to enqueue the correct filenames.

- **Source**: `assets/js/*.js`, `assets/scss/*.scss`
- **Build output**: `dist/*.min.js`, `dist/*.min.css`, `dist/manifest.json`
- **Config**: `webpack.config.js`

Install Node dependencies:

```bash
cd "public/wp-content/mu-plugins/novionline/novi-content-translator"
npm install
```

Run a dev watcher:

```bash
npm run dev
```

Build production assets:

```bash
npm run build
```

## Run unit tests

./vendor/bin/phpunit

./vendor/bin/phpunit --testdox

## Fixtures

Test fixtures live in:

- `tests/fixtures/`

They include real serialized Gutenberg snippets (including NectarBlocks) to prevent regressions across theme/plugin updates.

## Debugging

If you see Gutenberg “Block validation failed” errors:

- Compare “Content generated by `save()`” vs “Content retrieved from post body”
- Pay special attention to:
  - **Whitespace-only fragments** in strict wrappers (e.g. accordion content)
  - Inner blocks appearing **outside** their intended wrapper (placeholder/`innerContent` alignment)

## Development tips

- Prefer extending `BlockContentTranslator` block configs and adding a fixture + PHPUnit test for every new scenario.
- Keep changes minimal and avoid NectarBlocks implementation details where possible; the goal is stable translations across updates.
